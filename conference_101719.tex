\title{LifelongSceneDB: A Probabilistic Bitemporal Scene-Graph Store for Embodied Agents}

\author{\IEEEauthorblockN{Anonymous Authors}
\IEEEauthorblockA{Paper under submission}}

\maketitle

\begin{abstract}
Embodied agents operating in dynamic human environments require long-term memory to search for objects, resume interrupted tasks, restore previous states, collaborate with humans, and explain their decisions. Existing embodied memory systems typically rely on vector memories, 3D snapshots, or task-specific scene graphs, but lack database-level semantics for time, uncertainty, provenance, and hybrid querying. We present \sys, a memory database system that models noisy embodied observations as probabilistic bitemporal scene-graph facts. \sys maintains valid time and transaction time for object and relation facts, attaches confidence and provenance to each claim, and supports current, as-of, change, evidence, and task-oriented top-k queries. It further provides online maintenance mechanisms for conflicting and delayed observations, together with lightweight hybrid indexes for temporal, graph, spatial, confidence, and provenance predicates. We evaluate \sys on dynamic embodied memory workloads and downstream object-search and previous-state restoration tasks. The results will show whether database-level memory semantics improve query correctness under noisy and delayed observations, reduce query latency compared with scan-based baselines, and improve embodied task efficiency.
\end{abstract}

\begin{IEEEkeywords}
embodied AI, lifelong memory, temporal database, probabilistic data, scene graph, provenance, query processing
\end{IEEEkeywords}

\section{Introduction}

Embodied agents are increasingly expected to operate in long-horizon, dynamic human environments. In a household environment, a cup may be moved from a table to a sink by a human, a drawer may be opened and later closed, and a robot may resume a task after charging. To act efficiently, the agent must reason not only about the current camera view, but also about what it observed before, what has changed, which observations support a memory claim, and whether the current belief is reliable enough to act on.

Recent embodied memory systems have shown that memory is essential for embodied question answering, navigation, exploration, and manipulation. OpenEQA evaluates whether embodied agents can answer open-vocabulary questions from episodic memory or active exploration~\cite{openeqa}. 3D-Mem and related snapshot-based memories store compact visual memories for embodied exploration and reasoning~\cite{yang20253dmem}. DynaMem maintains dynamic spatio-semantic memory for open-world mobile manipulation~\cite{yu2024dynamem}. GraphPad uses mutable scene graphs and navigation logs as inference-time structured memory for embodied agents~\cite{graphpad}. Long-horizon VLN work such as MGDM further demonstrates that memory is critical for multi-stage embodied navigation~\cite{song2025lhvln}.

However, these systems usually treat memory as a task-specific module rather than as a database object with explicit query semantics. Vector or retrieval memories can find related frames, but they do not naturally distinguish the current state from a past state. Static scene graphs can represent object relations, but they collapse history and cannot answer when a relation changed. Dynamic embodied memories may update spatial representations, but they rarely provide database-level semantics for valid time, transaction time, uncertain facts, claim-level provenance, and hybrid temporal-graph-spatial-vector queries.

This paper formulates \emph{lifelong embodied memory management} as a data engineering problem. The input is a stream of noisy, delayed, and potentially conflicting embodied observations. The output is a persistent memory database that supports robot-facing queries such as: where is the mug now, where was it before breakfast, what changed in the kitchen, which frames support this claim, and should the robot re-observe before acting? These queries are not merely diagnostic: they are used by embodied agents to reduce blind search, restore previous states, resume interrupted tasks, and avoid unsafe actions under uncertainty.

We propose \sys, a probabilistic bitemporal scene-graph store for embodied agents. \sys represents each object or relation claim as a fact with valid time, transaction time, confidence, and provenance. It ingests noisy observation streams, incrementally maintains object and relation facts, resolves conflicting evidence through confidence updates, and supports current, as-of, change, provenance, and task-oriented top-k queries. To make these queries efficient, \sys maintains lightweight hybrid indexes over object identities, temporal intervals, regions, confidence values, and provenance links.

This work makes the following contributions:
\begin{itemize}
    \item We formulate lifelong embodied memory management as a data engineering problem over noisy and delayed embodied observation streams.
    \item We propose a probabilistic bitemporal scene-graph data model that represents dynamic world facts with valid time, transaction time, confidence, and provenance.
    \item We design online maintenance rules for supporting observations, conflicting observations, fact expiration, and evidence tracking.
    \item We provide robot-facing query interfaces and lightweight hybrid indexes for current, as-of, change, provenance, uncertain top-k, and task-oriented queries.
    \item We design a dynamic embodied memory workload and evaluate \sys against vector memory, static scene graphs, latest-wins temporal memory, and ablated variants on both database-level queries and downstream embodied tasks.
\end{itemize}

\section{Motivation}

\subsection{Why Embodied Agents Need Database Memory}

A long-term embodied memory database is useful only when past states support current tasks. We focus on four representative task families.

\textbf{Temporal object search.} A user may ask the agent to find ``the mug I used earlier.'' If the mug is no longer visible, the robot should query where it was last seen, whether it was later moved, and which location is currently most likely.

\textbf{Previous-state restoration.} A user may ask the robot to restore a kitchen to its state before breakfast. This requires as-of queries over the previous world state and change queries that identify objects moved after the target time.

\textbf{Long-horizon task resumption.} If a robot pauses a cleaning task to recharge, it must recover which subgoals have been completed and which objects or containers have already been manipulated.

\textbf{Evidence-aware explanation and safety.} If the robot plans to grasp an object whose location confidence is low, it should re-observe or ask a human. If it reports that a cup is in the sink, it should expose which observations support that claim.

These scenarios require more than retrieving related frames. They require a database that distinguishes current and historical states, tracks uncertainty, exposes evidence, and supports efficient hybrid queries.

\subsection{Running Example}

Consider the following episode:

\begin{tabular}{ll}
\toprule
Time & Event \\
\midrule

A vector memory may retrieve both table and sink observations; a static scene graph may only retain the latest state; a latest-wins temporal graph may be misled by the false detection. \sys maintains interval facts and evidence confidence, allowing it to answer that the cup is currently most likely in the sink, that it was on the table before 08:20, and that the sink claim is supported by observations around 08:30.

\section{Problem Definition}

\subsection{Observation Stream}

An embodied agent produces an observation stream $\mathcal{O}=\langle o_1,o_2,\ldots\rangle$. Each observation is a tuple
\begin{equation}
    o=(id,t_v,t_x,a,r,s,p,q,l,c,e),
\end{equation}
where $t_v$ is the event time in the world, $t_x$ is the arrival or ingestion time, $a$ is the agent, $r$ is the region, $s$ is the subject object, $p$ is a predicate, $q$ is the object or value, $l$ is the location, $c\in[0,1]$ is the observation confidence, and $e$ is an evidence reference such as a frame, sensor, or model output.

The stream may contain missed detections, false positives, relation errors, object identity switches, delayed observations, and out-of-order arrivals. \sys does not solve perception; it manages the uncertain outputs of perception systems.

\subsection{Embodied Memory Facts}

A memory fact is a tuple
\begin{equation}
    f=(s,p,q,[v_s,v_e),[x_s,x_e),\rho,E,\sigma),
\end{equation}
where $(s,p,q)$ is a scene-graph claim, $[v_s,v_e)$ is the valid-time interval, $[x_s,x_e)$ is the transaction-time interval, $\rho$ is the fact confidence, $E$ is provenance, and $\sigma$ is the fact status such as active, expired, or contradicted.

Valid time models when the fact is believed to hold in the world. Transaction time models when the database knew or stored the fact. This distinction is important for delayed observations and retrospective corrections.

\subsection{Query Workload}

We study six query classes.

\textbf{Current queries} ask for the best current state of an object or relation. \textbf{As-of queries} ask for the state at a past valid time. \textbf{Change queries} identify objects or relations that changed in a region or time range. \textbf{Provenance queries} return observations that support or contradict a claim. \textbf{Uncertain top-k queries} return ranked candidate locations or relations with confidence. \textbf{Task-oriented queries} combine semantic, temporal, spatial, and confidence constraints to support robot planning.

\section{LifelongSceneDB Data Model}

\subsection{Probabilistic Bitemporal Scene Graph}

\sys represents memory as a probabilistic bitemporal scene graph. Nodes correspond to objects, rooms, surfaces, containers, agents, or abstract task entities. Edges correspond to relations such as \emph{on}, \emph{inside}, \emph{near}, \emph{reachable}, \emph{seen-by}, and \emph{moved-to}. Each edge is a memory fact with valid time, transaction time, confidence, and provenance.

\subsection{Robot-Facing Interfaces}

Although \sys can expose declarative queries, robot planners interact with it through task-facing APIs:
\begin{itemize}
    \item \texttt{locate\_current(desc, constraints)} returns the most likely current state.
    \item \texttt{locate\_asof(desc, time)} returns the state at a valid time.
    \item \texttt{detect\_changes(region, range)} returns changed objects and relations.
    \item \texttt{get\_evidence(claim)} returns supporting and contradicting observations.
    \item \texttt{topk\_locations(desc, k)} returns uncertain candidate locations.
    \item \texttt{should\_reobserve(claim, threshold)} decides whether memory confidence is sufficient for action.
\end{itemize}

\section{Online Memory Maintenance}

\sys ingests observations online and updates memory facts. The maintenance procedure first identifies candidate facts related to the observation, then updates supporting facts, decays conflicting facts, inserts new facts when needed, and updates provenance and indexes.

For a supporting observation with confidence $c$, we update a fact confidence $\rho$ as
\begin{equation}
    \rho' = 1-(1-\rho)(1-c).
\end{equation}
For a conflicting observation, we decay the existing fact as
\begin{equation}
    \rho' = \rho(1-\gamma c),
\end{equation}
where $\gamma$ controls the strength of contradiction. If confidence falls below an expiration threshold, \sys closes the old valid interval and marks the fact as contradicted or expired.

\begin{algorithm}[t]
\caption{IngestObservation}
\label{alg:ingest}
\begin{algorithmic}[1]
\REQUIRE observation $o$, fact store $F$, indexes $I$
\STATE candidates $\leftarrow$ lookup related facts using object and region indexes
\FOR{each candidate fact $f$}
    \IF{$o$ supports $f$}
        \STATE update $f.confidence$ with support rule
        \STATE add $o$ to supporting provenance of $f$
    \ELSIF{$o$ conflicts with $f$}
        \STATE decay $f.confidence$ with conflict rule
        \STATE add $o$ to contradicting provenance of $f$
        \IF{$f.confidence$ below threshold}
            \STATE close $f.valid\_end$ at $o.event\_time$
            \STATE mark $f$ as contradicted
        \ENDIF
    \ENDIF
\ENDFOR
\IF{no active fact explains $o$}
    \STATE insert new fact with valid time $o.event\_time$ and transaction time $o.arrival\_time$
\ENDIF
\STATE update temporal, object, region, confidence, and provenance indexes
\end{algorithmic}
\end{algorithm}

\section{Query Processing and Indexing}

\sys maintains lightweight hybrid indexes for the query workload:
\begin{itemize}
    \item an object index maps object identities or classes to fact identifiers;
    \item a temporal index stores valid intervals for as-of and change queries;
    \item a region index maps rooms or surfaces to active objects;
    \item a confidence index supports top-k uncertain state queries;
    \item a provenance index maps facts to supporting and contradicting observations.
\end{itemize}

The current prototype uses a rule-based planner. If a query specifies an object, the object index is applied first; if it specifies time, the temporal index filters valid intervals; if it specifies region, the region index filters spatial candidates; final candidates are ranked by confidence and optionally returned with provenance.

\section{Experimental Evaluation}

\subsection{Research Questions}

Our evaluation is designed around four questions:
\begin{itemize}
    \item RQ1: Does \sys answer embodied memory queries more accurately than vector, static-graph, and latest-wins memory baselines?
    \item RQ2: Is \sys robust to noisy and delayed observations?
    \item RQ3: How much do bitemporal time, confidence, provenance, and indexing contribute?
    \item RQ4: Does \sys improve downstream embodied object search and previous-state restoration?
\end{itemize}

\subsection{Dynamic Memory Workload}

We generate synthetic dynamic embodied episodes over household-style scenes. Each episode contains objects, regions, observations, and events such as \texttt{MOVE}, \texttt{OPEN}, \texttt{CLOSE}, \texttt{HIDE}, \texttt{REVEAL}, \texttt{HUMAN\_MOVE}, and \texttt{ROBOT\_OBSERVE}. Ground-truth events are converted into noisy observation streams with missed detections, false detections, wrong locations, delayed arrivals, and out-of-order observations.

Queries and answers are generated from ground truth. A movement event such as \texttt{MOVE(cup, table, sink, 08:20)} produces current, as-of, change, and provenance queries. This lets us evaluate both database correctness and task usefulness with known answers.

\subsection{Baselines}

We compare against the following baselines:
\begin{itemize}
    \item \textbf{Vector memory}: retrieves observations by text or feature similarity.
    \item \textbf{Static scene graph}: keeps only the latest active relation.
    \item \textbf{Latest-wins temporal memory}: maintains history but accepts the latest observation as truth.
    \item \textbf{No-confidence}: maintains temporal facts but ignores confidence fusion.
    \item \textbf{No-bitemporal}: uses a single timestamp rather than valid and transaction time.
    \item \textbf{No-index}: scans all facts for each query.
\end{itemize}

\subsection{Metrics}

Database-level metrics include current-state accuracy, as-of accuracy, change detection F1, provenance precision and recall, stale fact rate, query latency, update throughput, and memory footprint. Task-level metrics include object-search success, wrong-location visits, search steps, restoration accuracy, and unnecessary moves.

\section{Related Work}

\subsection{Embodied Question Answering and Embodied Memory}
OpenEQA evaluates open-vocabulary embodied question answering under episodic memory and active exploration settings~\cite{openeqa}. It is a benchmark rather than a memory database. \sys can be used as a memory backend for embodied QA agents by providing structured and provenance-aware memory contexts.

\subsection{3D and Dynamic Scene Memories}
3D-Mem stores compact 3D scene memories for embodied exploration and reasoning~\cite{yang20253dmem}. DynaMem maintains dynamic spatio-semantic memory for open-world mobile manipulation~\cite{yu2024dynamem}. These systems show that dynamic memory is useful for embodied agents, but their main focus is agent performance and spatial memory, not database-level temporal, uncertainty, provenance, and hybrid query semantics.

\subsection{Structured Agent Memory}
GraphPad uses mutable scene graphs, navigation logs, and scratchpads as structured inference-time memory for embodied agents~\cite{graphpad}. In contrast, \sys is a persistent lifelong memory backend with bitemporal facts, confidence, provenance, and database query interfaces.

\subsection{Long-Horizon Vision-Language Navigation}
Long-horizon VLN work such as MGDM uses short-term observation memories and long-term retrieval from navigation datasets to guide multi-stage navigation~\cite{song2025lhvln}. This memory is model-internal and action-oriented. \sys instead stores the agent's own dynamic world state as a queryable database.

\subsection{Temporal, Probabilistic, Provenance, and Graph Databases}
\sys builds on ideas from temporal databases, probabilistic data management, graph data management, provenance, spatial data, and vector retrieval. The contribution is not to reinvent these individual database concepts, but to combine them into a system model for noisy, dynamic, and task-facing embodied memory.

\section{Conclusion}

This paper introduces \sys, a probabilistic bitemporal scene-graph store for embodied agents. \sys treats long-term embodied memory as a data engineering problem: noisy observations are converted into queryable world facts with time, confidence, and provenance. The system supports current, as-of, change, evidence, and task-oriented queries, and uses lightweight hybrid indexes for efficient execution. The planned evaluation studies whether these database-level memory semantics improve robustness, query efficiency, and downstream embodied task performance.
